# iOS Access 现状与界面改造分析

检查基线：`origin/develop` 的 `7d47f9408c50e3d5cd547231db9e2a9b79d245a4`（2026-11-16）。本报告先记录源码事实；不将历史测试、配置存在或界面展示作为生产服务验收。

## 核心判断

iOS 已有网站级连接、失败恢复、普通/私密隔离、用量读取及账户下载授权等组件，但它们没有形成完整的“登录账号 → 支付权益 → 网站连接 → 统一计量”的用户产品。首要问题是授权和用量来源分离，其次是技术信息过多、状态难以理解。修改文案只能改善交互，不能消除后端和路由缺口。

| 现状 / 证据 | 对用户或交付的影响 | 建议 |
| --- | --- | --- |
| `AccessSiteProxyToggleView` 默认展示匿名节点 ID、协议组合、路由和测试说明；用量直接堆在当前网站表单 | 不符合老板“隐藏细节”的要求 | 本次改为网站开关、实际状态、作用范围和用量入口；高级选项折叠 |
| `AccessEmbeddedProxyEntryFactory` / `AccessHostStoreCoordinator` 为 WebKit 准备本地配置的连接入口；`AccessAccountSession` 的授权另用于账户下载 | 展示账号额度不能证明该网站流量消耗同一账号权益 | 生产阶段统一网页/资源/下载的授权、续期、撤销与结算 |
| `AccessSubscriptionUsageSession.product()` 在配置了本地测试节点的 dev/alpha/beta 选择共享订阅查询，预期测试额度固定；数据是该测试订阅的总计 | 不能声称是个人套餐、当前网站或当前设备流量 | 显式标注共享测试数据；上线个人账本后切换数据源，迁移需要单独验收 |
| `AccessAccountSession` 有设备 Keychain、绑定、刷新、退出及授权撤销；没有面向消费者的登录/支付界面和完整凭据签发流程 | 已有会话组件不等于用户能购买并登录 | 对接服务端真实账号与订单；本次不伪造购买按钮或会员状态 |
| `AccessAccountUsagePresentation` 保留十进制整数字节并按单调时间判断新鲜度；测试订阅无服务端测量时间 | 查询刚返回也不能保证用量实时 | 保留陈旧/测量时间未知提示；计费与停流仍由后端负责 |
| 手动开关意图、自动恢复附着、入口连接就绪是不同状态 | 手动关闭时仍可能有已授权自动恢复连接；只看开关会误判 | 同屏显示实际状态，保留自动恢复选项；不把开启开关标成已保护 |
| `BrowserSession` 只对选定网络错误与可安全重放的主框架 GET/HEAD 开放恢复；排除请求体/Authorization、TLS、离线等 | 普通 HTTP 拦截页可能加载成功，现有错误回调不会出现；Cloudflare 提示未落地 | 保留重放限制；单独设计 CDN 样本识别，不扩大到所有错误 |
| 当前错误横幅将错误、自动恢复说明和多个动作都染红，正文暴露内部错误 | 信息拥挤、主动作不突出 | 本次突出“开启并重试”，错误详情折叠，普通重试保留 |
| `beginPrepare` 的显式重试/地址打开会为目标网站开启连接意图 | 按钮不能说“仅这一次” | 文案明确对本站生效；持久化/跨会话保留范围另行确认 |
| `AccessHostStoreCoordinator.snapshot` 未映射正在准备的 operation，尚未就绪时一律可能显示不可用 | 准备过程被误读为失败 | 本次增加 `.connecting` 映射和对应回归断言；连接协议不变 |
| `AccessAccountUsageRefreshCoordinator` 是应用级调度：激活即查询，无可见用量页时仍低频查询 | 隐藏私密页中的额度不等于应用停止普通账号的后台查询 | 本次保证私密用量页不增加普通查询观察者；是否在仅剩私密窗口时暂停全局查询需单独确认 |
| 原 `intentLine` / `attachmentLine` 返回动态字符串，视图用 `Text(String)` | 这些文字不走 SwiftUI 的本地化 key 查找 | 本次显式按本地化键渲染，并增加新文案的语言资源 |

界面中还区分了网站地址和服务节点地址。模拟器里的 `127.0.0.1` 是测试网页的回环地址，用户在网站设置、加载失败提示和收起的地址栏看到“本机页面”。编辑地址时保留完整网址，公网网站继续显示实际域名，方便用户核对开关的作用对象。

## 已有保护边界应保留

- 网站开关绑定实际目标 host；失败目标和 WebKit 最后提交网址可能不同。
- 失败票据绑定 tab、scope、navigation、host revision、operation，防止旧导航或旧按钮重试新目标。
- 请求体、非 GET/HEAD、授权头等不能被无条件重放；自动恢复不能扩大网站授权。
- 准备有截止时间、重复动作合并；已绑定入口故障不能静默回退原连接。
- 普通/私密授权和存储隔离；私密页面不展示普通账户额度、不因打开页面增加普通用量观察者；应用级后台查询单独管理。
- 用量读取失败保留明确的不可用/陈旧状态，不当作余额零、不凭 UI 决定流量放行。

## 服务端已有原型，不应重复立项

`services/access_account/README.md` 描述了：S1 账户级权益读取和手工发放的会话凭据；S2 本地受信任 sandbox 订单与幂等权益发放；S3 短期 CONNECT 凭据、续期/撤销和节点侧校验。这些可作为联调基础。

其文档同时说明：sandbox 订单不是生产支付渠道验签；节点/服务端共享的受控授权原型不代表生产节点编排；Alpha 面板共享计数不等于每账号周期账本；字节级结算和耗尽控制仍须独立验收。不要将“已有后端原型”写成“没有后端”，也不要写成“付费服务已经上线”。

## 本次界面实现与验证边界

本次修改用户呈现、必要导航及准备状态映射，保留连接授权和计费边界。覆盖当前网站、失败/待连接提示、账号与用量页，补充本地化及回归验证。无真实支付、真实节点凭据或生产账号参与测试。

生产首版还需完成[需求文档](../plans/account-access-v1.zh-CN.md)的 C2–C5、S1–S5、N1–N3 联调。真机、签名/商店、生产节点、支付渠道、CDN 样本和发布不能由模拟器或源码检查代替。最终测试与独立审查结果记录在本次交付说明中，按候选版本绑定。

## Protected Android fork release opt-in

Unsigned runner qualification does not enable signing. The protected Android fork path additionally requires `AEGIS_ANDROID_RELEASE_ENABLED=true`, the existing Android rehearsal opt-in, configured fork repository ID, exact source SHA, and the fixed acceptance branch or matching Android candidate tag. It must work while shared `AEGIS_RELEASE_ENABLED` and `AEGIS_RELEASE_REHEARSAL` remain disabled. Both reusable release preflight and Android Simple/Full backend receive the dedicated flag; candidate Draft request routing retains that exact fork identity. Upstream main/quality rules and all non-Android opt-ins retain their current behavior. Environment protections and signing-runner readiness remain separate gates, left disabled until qualified.

Enabling shared flags was rejected because it also changes other platform admission. Overriding shared flags inside jobs was rejected because it obscures which permission enables Android. An explicit Android flag is the selected implementation under the user's authorized blocker resolution. This code change creates a new source candidate and requires fresh contracts/native acceptance; fedd39e proofs remain evidence only for fedd39e.

## Android signing token and final source check

The shared package job keeps its existing `contents: read` permission. Only Android receives its ephemeral job token, in a fresh Admin/source preflight before the signing step and in the package entrypoint that repeats the Admin check. Since compilation can take hours, the actual Android signing method also checks a clean checkout against immutable Actions SHA and repeats Admin/source admission before reading the Upload key. Local signing behavior is unchanged. Other platforms retain their token mapping and permission behavior. A hosted, unsigned `read-token-admission` job with only `contents: read` must exercise the real GitHub Admin/run/jobs/workflow/ref/commit GETs for the exact public configured fork and source before native qualification. Source admission requires this job together with contracts and native at the same latest successful run/attempt, and rejects a fork visibility change. Missing API access fails before signing; a successful probe is not a signed-package acceptance.

Granting `actions: read` to the shared package job was rejected because it changes other platform permissions. A second packaging backend was rejected because it duplicates signing and receipt handling. The selected minimal token mapping and separate unsigned capability check keep the existing Tag and Simple/Full paths, without service-account changes, new credentials, main integration or shared release enablement.

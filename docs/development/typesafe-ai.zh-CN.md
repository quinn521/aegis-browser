# TypeSafe AI 决策接入

## 范围

TypeSafe AI 的 Jev 接在 Browser Agent 的目标理解入口，用于选择已有工作流、入口类型和任务所需的模型能力。浏览器再从用户维护的模型池中确定性选择主模型和一个回退模型；计划生成、工具参数和最终回答都绑定到这份任务级路由快照，不会在任务中途因设置变化而漂移。

路由模式包括固定模型、均衡、质量优先、成本优先和仅本地。固定模式保留原有单模型行为；三个自动模式根据 Jev 返回的能力要求，以及候选模型的能力、质量、延迟、价格和优先级进行排序。仅本地模式排除云端候选，并完全绕过 TypeSafe 网络请求。

TypeSafe 能力默认关闭。启用后，只要路由模式不是仅本地，输入的任务目标仍会发送给 TypeSafe；设置页必须在启用前说明这一点。未启用、无有效密钥、仅本地模式或隐身 Profile 不调用 TypeSafe。

## 接口与数据边界

官方接口核对日期：2026-09-21。

- 固定接口：`POST https://api.typesafe.ai/v1/systemone`。
- 模型：`jev-latest`；这是服务商可更新的别名，行为验收需记录实际返回的版本。
- 鉴权：独立的 TypeSafe Bearer API key，不复用 OpenAI、Anthropic、Gemini 或本机模型的凭据。
- 请求只包含用户输入的任务目标和浏览器预定义的问题。用户主动写进目标的内容也会被发送；模型池、端点、页面 DOM、历史、Cookie 和任何模型密钥都不会附加到请求。
- Choice 答案必须属于预定义枚举，类型、置信度、概率分布和选中项均需验证。
- TypeSafe 输出工作流、入口类型、推理强度、上下文长度和结构化输出要求。它不选择具体模型，也不生成 URL、搜索词、摘要或工具调用。具体模型由浏览器本地的确定性路由器选择；入口参数由浏览器构造，并继续经过现有用户意图约束。

参考：[API reference](https://docs.typesafe.ai/api)、[Quick start](https://docs.typesafe.ai/introduction/quickstart)、[Introduction](https://docs.typesafe.ai/introduction)。

## 执行与回退

默认路径保持已有模型路由。启用 TypeSafe 后，对符合条件的目标执行一次最多 2 秒的决策请求。每个答案的置信度均须达到 0.8，且选中项必须与概率分布一致。合格结果参与工作流和模型能力选择；低置信度、无效结果、网络错误、限流和超时使用浏览器内置的保守能力要求，不在入口中循环重试。

浏览器最多保存 8 个模型池条目。自动路由先过滤不可用、能力不足或不符合仅本地约束的候选，再按所选模式稳定排序；相同分数使用优先级和稳定 ID 打破平局。成本未知保持为未知，不按免费模型处理。任务创建时冻结主模型、一个回退模型、路由模式和目录修订号。

只允许一次生成模型回退：首个计划请求发生网络、超时、限流、服务繁忙或临时服务错误，且尚未产生工具调用时，先记录回退事件并切换到冻结的回退模型。格式错误、永久 HTTP 错误、计划修复请求、执行阶段和监控阶段不自动换模型，避免重复动作和不可审计的模型漂移。

决策本身不授予工具权限。任务授权卡、来源和标签页范围、下载或购物的最终确认、用户目标中的否定约束继续由浏览器维护。显式 URL 和当前页面入口保留原有处理逻辑。

密钥只通过密码字段写入浏览器进程，持久化时加密；WebUI 只读取“是否已配置”等状态。固定服务地址，拒绝重定向，避免鉴权头转发到其他目的地。关闭能力、清除或替换密钥、取消任务以及销毁 Profile 时，应使在途请求失效，旧结果不能启动后续模型调用。

## 配置与使用

1. 在包含本次代码的 Aegis 构建中打开 Browser Agent，在设置中添加模型池条目。每个条目配置 provider、model、base URL、本地/云端属性、能力、质量分、延迟分、可选价格和优先级。
2. 选择固定、均衡、质量、成本或仅本地模式。固定模式继续使用选定的单一模型；自动模式至少需要一个满足任务能力要求的可用候选。
3. 如需 Jev 决策，展开独立的 TypeSafe 设置，阅读任务目标发送说明，输入从 [TypeSafe 控制台](https://console.typesafe.ai/) 取得的 API key，开启后保存。不要将密钥提交到 Git、PR 或测试日志。
4. 输入新任务，检查计划详情中的主模型、回退模型、目录修订号、TypeSafe 结果和任务级指标，再按现有授权流程执行。

## 任务级观测与启用前后比较

每个任务持久化以下观测字段：路由模式、模型目录修订号、主模型和回退模型；TypeSafe 是否尝试、是否达到置信度门槛、结果类型、实际 Jev 模型、决策摘要、输入/输出 token 和延迟；是否发生生成模型回退；生成模型输入/输出 token 和累计延迟。UI 根据任务冻结的模型价格估算生成成本；价格未知时保持未知。TypeSafe 服务成本没有本地价格元数据，因此不并入生成成本。

启用前后比较使用同一批冻结任务、相同授权策略、相同浏览器版本和相同执行上限，至少运行固定模式基线和一个自动模式候选。不要用线上自然流量直接替代受控对照；任务难度、供应商故障和缓存命中会造成偏差。

| 指标 | 定义 | 判定方式 |
| --- | --- | --- |
| 正确率 | 任务最终结果满足预先标注的验收条件的任务数 / 可判定任务数 | 固定 benchmark 与盲评标签；终态 `completed` 只能作为运行代理，不能代替正确性标注 |
| 回退率 | `fallback_used=true` 的任务数 / 发起过生成模型请求的任务数 | 按路由模式、主模型、错误类型分别统计；同时检查回退后正确率 |
| 延迟 | TypeSafe 延迟、生成模型累计延迟和任务端到端耗时 | 报告 p50、p95、p99；TypeSafe 未调用时记为不适用，不能记为 0 ms 改善 |
| 成本 | 已知价格候选的输入输出 token × 每百万 token 价格 | 分模型、分模式汇总；未知价格和 TypeSafe 成本单列，不补零 |

建议分三阶段放量：先离线回放至少 100 个覆盖搜索、当前页、浏览器原生入口和高推理任务的冻结样本；再对内部用户做 10% 影子决策，只记录候选而不改变实际模型；最后以 10% → 25% → 50% 梯度启用自动路由。每一阶段都按目录修订号切片，若正确率下降超过 2 个百分点、p95 端到端延迟上升超过 20%、回退率超过 10%，或单位成功任务成本上升超过 15%，停止扩量并恢复固定模式。具体阈值在获得首轮基线后可通过独立评审调整。

## 验收

| 层级 | 需要证明的行为 |
| --- | --- |
| 协议单测 | 请求使用官方 schema；合法枚举通过，未知枚举、错误类型、低置信度、缺失或矛盾概率拒绝。 |
| 网络单测 | 固定目的地、独立鉴权、Cookie 排除、重定向拒绝、响应大小与超时限制、错误回退及取消。 |
| 路由单测 | 各模式过滤与稳定排序正确；能力不足被排除；未知成本不当作零；仅本地排除云端；主备候选不同。 |
| 服务回归 | 默认关闭无新增网络；仅本地零 TypeSafe 请求；临时计划失败最多回退一次；永久错误和执行阶段不回退；隐身禁止；配置变化后的过期回调被丢弃；已有意图与权限约束不变。 |
| 持久化 | 任务恢复后主备模型、模式、目录修订号和观测指标不变；旧数据库可迁移；无效指标拒绝加载。 |
| WebUI | 默认关闭；云端发送说明可见；密钥写入后不回显；保存失败可见；模型池可编辑；主备模型和任务指标可见。 |
| 原生集成 | 最终代码进入固定 Chromium GN 目标，执行相关 GTest，并在侧栏验证设置、启动、回退和取消。 |
| 真实服务 | 使用有权限的 TypeSafe key，记录返回模型版本、成功/失败、延迟与回退；不记录密钥或完整任务目标。 |

仓库基础质量门、独立 Review、GitHub CI、Chromium 构建和真实 API 联调分别报告。Node WebUI 测试或静态 GN 检查不代表 C++ 行为测试已通过。没有实际执行的测试不标为通过。

## 回滚

将路由模式切换为固定即可恢复单一生成模型；切换为仅本地会同时停止 TypeSafe 请求并排除云端候选。关闭 TypeSafe 或清除密钥只关闭 Jev 决策，自动路由仍可使用浏览器内置的保守能力要求。代码回滚通过普通可审查 revert，保留已有生成模型凭据。
